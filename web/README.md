# 冲撞迷阵 Maze Dash — 网页版 (Web Port)

把 Android 版《冲撞迷阵 Maze Dash》移植成可以直接在浏览器里玩的网页版。

**这不是重制版，而是移植版**：运行的仍然是原 APK 里的游戏代码、关卡数据与全部美术/音频资源，
只是把 Android 原生运行时（Cocos Creator 2.0.2 的 jsb 引擎 + 广告/支付/振动等原生桥接）
换成了浏览器运行时。原游戏的 4 个场景、290 个关卡、8 个世界、皮肤、任务、商店界面等
全部按原样呈现。

---

## 快速开始

### Windows

双击 **`start.bat`**，浏览器会自动打开 `http://localhost:8099/`。

### macOS / Linux

```bash
./start.sh          # 或 ./start.sh 8123 指定端口
```

### 手动启动（推荐 Node）

```bash
node serve.js       # 默认 8099 端口
# 然后浏览器打开 http://localhost:8099/
```

也可以用任意静态服务器，只要它把本目录当作站点根目录：

```bash
python3 -m http.server 8099
npx serve -l 8099 .
```

> **⚠️ 必须通过 HTTP 服务器打开，不要双击 `index.html`。**
> 游戏用 XHR 读取 `res/` 下的 350 个资源文件，浏览器在 `file://` 协议下会**全部拦截**，
> 结果是进度条一直卡住不动（页面会显示一条明确的提示告诉你该怎么做）。
> 请双击 **`start.bat`**（Windows）或执行 **`node serve.js`**，然后访问 `http://localhost:8099/`。
> 用 Node 的 `serve.js` 还可以获得 Range 请求支持（音频更稳）。

已经验证的浏览器：Chrome / Edge（Chromium 内核）。Firefox、Safari 亦可（WebGL + Web Audio）。

## 操作方式

| 平台 | 操作 |
| --- | --- |
| 手机 / 平板 | 在棋盘上滑动（原版操作方式） |
| 桌面鼠标 | 按住鼠标拖动 = 滑动 |
| 键盘 | `↑ ↓ ← →` 或 `W A S D` |

游戏规则：蛇头朝一个方向冲撞，撞到墙才停下，经过的格子会变成身体；
**把所有地板格子都填满即过关**。

## 运行环境要求

- 任意现代浏览器（需要 WebGL 与 Web Audio）
- 一个静态文件服务器：Node.js（推荐，附带 `serve.js`）或 Python 3

进度保存在浏览器的 `localStorage` 里（键名经过原游戏的 `compile()` 混淆，例如 `pass_info`）。
清除站点数据即可重置进度。

## 相比原版的改动

原版游戏代码 **一行未改**（`src/` 与 `res/` 全部与 APK 内文件 SHA-256 一致）。
所有改动都发生在引擎替换与适配层 `web-port.js` 中：

1. **引擎替换** — 原 APK 带的是 `cocos2d-jsb.js`（Android 原生引擎，浏览器里无法运行）。
   网页版换成用同一版本（2.0.2，tag `2.0.2`）源码构建的浏览器引擎 `cocos2d-js.js`。

2. **原生桥接自然失效** — 原代码通过 `jsb.reflection.callStaticMethod(...)` 调用
   Android 的广告、支付、振动、GDPR 判定。这些调用点原本就包在 `try{}catch{}` 里，
   网页版故意不定义 `jsb`，于是它们全部退化为静默空操作。
   **没有广告、没有内购、没有振动。**

3. **体力系统改为不受限** — 原版 10 点体力、每 5 分钟恢复 1 点，补充体力靠看广告或内购。
   去掉广告/内购后玩家会被锁死在 10 关，因此 `web-port.js` 把体力上限提到 999 并预置满值，
   首次进入再赠送 99 个提示。关卡进度、任务、解锁逻辑一律未动。

4. **音频解锁与容错** — 浏览器要求先有用户操作才允许播放声音，因此在首次点击时恢复
   AudioContext。另外若音频下载被浏览器插件/下载器（如 IDM 的 “Advanced Integration”）
   拦截成空响应，会先用带尾斜杠的 URL 重试（可绕过媒体拦截规则），仍失败则回退成静音缓冲，
   保证依赖音频的场景不会卡在加载中。

5. **桌面键盘操作** — 原版只支持滑动。适配层通过向 canvas 派发合成鼠标事件实现方向键/WASD
   操作（引擎本身会把鼠标事件转成触摸事件）。

6. **启动失败会自我说明** — 若用 `file://` 直接打开，脚本在启动前就能检测到，并把「该怎么做」
   连同实时诊断（协议、成功/失败的资源请求数与示例）一起显示出来，而不是让进度条无声卡住；
   其他原因的加载失败也会在 25 秒后给出同样的诊断。

5. **桌面键盘操作** — 原版只支持滑动。适配层通过向 canvas 派发合成鼠标事件实现方向键/WASD
   操作（引擎本身会把鼠标事件转成触摸事件）。

## 已知问题（均为原版数据/设计层面，非移植缺陷）

- **第 5 关（mapId 5）内置提示串不完整。** 原版数据里该关的解是 `LURDRDL`，
  但按游戏自身规则重放到第 4 步就会被自己身体挡住，无法填满棋盘。
  该关本身有解（例如 `RDLULD`），玩家可以正常通关，只是那一条提示链的后半段不可靠。
  其余 289 关的内置解都能完整重放通关，说明这是孤立的原始数据问题。

- **原版为竖屏 720×1280**。网页版把舞台固定成 9:16 居中显示，横屏窗口下会有黑边。
  想全屏体验可以在手机浏览器里打开，或把窗口调成竖向。

- **首次点击前不会出声。** 这是浏览器自动播放策略，不是 bug；点一下画面即可。
