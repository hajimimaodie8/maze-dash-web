## 0. 一句话现状

原版 Android 游戏《冲撞迷阵 Maze Dash》已移植为网页版（单文件直装 + HTTP 构建），
**界面已适配宽屏、去广告去付费、并已开始做「关卡编辑器」**。
已实测：**3 个主角可用**、**多对彩色传送门（同色才传送）功能可用**、**自定义世界里的关卡能进能玩**。

## 3. 关卡数据模型（研究结论，编辑器据此设计）

三层文件 → 运行层**一张二维整数矩阵**：

```
data/package1..8.txt   #mapId + 字符网格        （作者层）
data/levels.json       {id, wordId, levelId, mapId, sz_solution}   （配置层）
conf.all_Level[mapId]  [[y][x] 整数矩阵]        （运行层，写编辑器只需写这一张）
```

**字符 ↔ 数值**（`docs/level-format.md` §2 有完整表）：

| 字符 | 含义 | 值 | 备注 |
| --- | --- | --- | --- |
| `0` | 地板 | `1` | **过关 = 蛇身填满所有地板** |
| `W` | 墙 | `0` | |
| `C` | 主角 | `-1` | **可以放多个**（已实测 3 个正常） |
| `B` | 砖块 | `-4` | |
| `^ > V <` | 箭头 | `5 6 7 8` | 强制改向；反向时视为墙 |
| `P` | 传送门 | `2` | **必须保持 2**，否则渲染器不画门 |
| `K` | 钥匙 | `4` | |
| `L` | 锁 | `-3` | |
| （运行期） | 蛇身 | `-2` | 不要写进文件 |

运行时引擎把它克隆成 **两个平行矩阵**：`Level_data[y][x]`（地形/规则）+ `Level_item_data[y][x]`（道具状态）。
**背景不在关卡 JSON 里** ✗：由世界 id 决定（`vignettes/stage{worldId}_bg1`）+ 随机装饰。

## 4. 彩色传送门扩展（已实现，功能已验证）

引擎原生行为（源码证据）：`game_map.getOutPortal()` = **从头扫描全图，返回第一个其它传送门** ✗
→ 多对门会全部连到一起。为此在 `custom-tab.js` 里**包装该实例方法**：

* 颜色存在**旁表**（`activePortalColours`，键 `"x,y"`），**不要写进格子值**（写进去渲染器就不画门了）
* 同色才配对；找不到同色伙伴 → **原地不动**（＝无法传送）
* 落点：`/gameScene/Canvas/backgroup/game_map` 组件上的 `getOutPortal`（实例级替换，不动全局）

**已实测配对**（测试关卡：左房间 3 主角 + 门下排；右房间门贴顶；紫/红/蓝）：

```
右 7,1(紫) -> 左 1,2(紫)      左 1,2 -> 7,1
右 8,1(红) -> 左 2,2(红)      左 2,2 -> 8,1
右 9,1(蓝) -> 左 3,2(蓝)      左 3,2 -> 9,1
```

## 6. 硬规则（都是踩坑换来的，务必遵守）

1. **只做整函数替换或有界行替换** ✗ 绝不用"猜字符串/正则"盲改（多次静默 0 匹配、还报成功）。
2. **`node --check` 失败必须立即中止** —— 不得继续构建/提交（我曾因此推过坏构建，事后 revert）。
3. **验证必须针对用户运行的那个产物**：单文件版用 `file://` 跑探针 ✓；只测 HTTP 构建当作已验证 ✗。
4. **界面改动必须亲眼看截图** ✓ —— 节点数字 ≠ 看得见（我曾用"24 个色块"证明"看得见"，屏幕上却什么都没有）。
5. **改动游戏自带节点前，先打印它的名字/尺寸/颜色** —— 我因猜错把**主角**当成图案隐藏，导致标题页只剩一张脸、主角变白。
6. **指代不明的反馈先问清位置**（"这个是白的/这个不对"）—— 我曾猜错两次，白改进度条和箭头又全部还原。
7. **改"全局属性"（字体/尺寸/层级）前，先列出所有依赖它的地方**。
   CJK 字体切换就漏了这一条：换了字体却没同步行高，导致**全程序文字上半被截**。

## 8. 关键 ID 规则（防串档）

自定义世界 id **从 100 起**、关卡/地图 id **从 10000 起**（测试关卡用 101 / 10101）。
原版：世界 1..8，关卡 id 与 mapId 各自成体系，**不要覆盖**。

## 9. 用户偏好（重要）

* 界面要**贴合原版画风**：圆角面板用游戏自己的 `default_panel`，颜色取 `theme_cfg` 槽位，
  动效用 `pressFeedback`/`animateIn`（0.05–0.22s + `cc.easeSine*`），**不要自造突兀样式**。
* **动效必须丝滑**、字号不能过小、**避免小框框**。
* 中文界面文字必须能显示（系统字体 + 行高 1.45×）。
* 交付时**给本地文件**（在线版有延迟）。
